# 5G RACH Procedure Deep-Dive

## Contention-Based Random Access Capture and Msg1–Msg4 Timing Analysis

> A practical 5G Standalone (5G SA) signalling analysis project using **UERANSIM, Open5GS and Wireshark** to investigate UE registration, Random Access-related activity, NGAP/NAS signalling, timing behaviour and multi-UE registration.

---

## 📌 Overview

The **Random Access Channel (RACH)** procedure is an important part of 5G NR because it allows a UE to establish uplink synchronisation and gain access to the network.

This project performs a practical investigation of the **5G Standalone UE registration procedure** using a simulated 5G environment consisting of:

- **UERANSIM** – 5G UE and gNB simulator
- **Open5GS** – 5G Core Network
- **Wireshark** – packet capture and protocol analysis

The experiment focuses on studying the relationship between the simulated radio-link activity and the subsequent **NGAP and NAS signalling** involved in UE registration.

Multiple UEs were configured and tested to analyse their individual registration procedures and timing behaviour.

---

# 🎯 Objectives

The main objectives of this project are:

- Simulate UE registration using UERANSIM and Open5GS
- Capture signalling traffic using Wireshark
- Observe UERANSIM Radio Link Simulation (RLS) traffic
- Analyse NGAP and NAS signalling
- Identify the `InitialUEMessage`
- Analyse the NAS `Registration Request`
- Study Authentication signalling
- Study Security Mode procedures
- Analyse Initial Context Setup
- Analyse PDU Session Resource Setup
- Perform packet timing analysis
- Configure and test multiple UEs
- Analyse multi-UE registration behaviour
- Investigate the contention-based Random Access procedure
- Document the limitations of observing physical RACH parameters in a software-based simulation

🔄 5G Contention-Based RACH Procedure

The standard 4-step contention-based Random Access procedure consists of:

                         UE                         gNB
                          │                          │
                          │                          │
                          │──── Msg1 ──────────────►│
                          │    PRACH Preamble       │
                          │                          │
                          │◄─── Msg2 ───────────────│
                          │    Random Access        │
                          │    Response (RAR)       │
                          │                          │
                          │──── Msg3 ──────────────►│
                          │    Scheduled UL         │
                          │                          │
                          │◄─── Msg4 ───────────────│
                          │    Contention           │
                          │    Resolution           │
                          │                          │
                          ▼                          │
                    UE continues with                │
                  higher-layer signalling            │
Msg1 – PRACH Preamble

The UE initiates the Random Access procedure by transmitting a PRACH preamble.

The purpose of Msg1 is to request access to the radio network and allow the gNB to detect the UE's random access attempt.

Msg2 – Random Access Response

The gNB responds with a Random Access Response (RAR).

The RAR can contain:

Timing Advance
Uplink Grant
Temporary C-RNTI
Msg3 – Scheduled Uplink Transmission

Using the resources provided by the RAR, the UE transmits Msg3.

Msg3 carries information required for establishing the UE connection and resolving contention.

Msg4 – Contention Resolution

The gNB responds with Msg4 to resolve contention between UEs that may have selected the same PRACH preamble.

After successful contention resolution, the UE proceeds with the subsequent connection and registration procedures.

⚠️ RACH Observation Limitation in UERANSIM

An important finding of this project is that UERANSIM provides a software-based radio link simulation rather than a real over-the-air 5G NR physical interface.

Therefore, the Wireshark capture does not expose physical-layer PRACH information in the same manner as an actual RF capture.

The following physical-layer information could not be directly observed as conventional NR PHY/MAC packets:

PRACH waveform
Actual physical PRACH preamble
Physical-layer RA-RNTI
PHY/MAC-level Random Access Response
Physical Msg3
Physical Msg4

Instead, the experiment uses the observable UERANSIM RLS traffic and correlates it with the higher-layer NGAP/NAS signalling.

This limitation is an important result because it demonstrates the difference between analysing:

Real 5G NR air-interface traffic
             vs.
Software-simulated 5G traffic

📝 Registration Request

The NAS Registration Request represents the UE's request to register with the 5G Core Network.

The registration procedure observed in the capture corresponds to:

Registration Type:
Initial Registration

This is the first major NAS message associated with the UE registration process.

🔐 Authentication Procedure

After receiving the Registration Request, the network initiates UE authentication.

The observed signalling includes:

Authentication Request
        │
        ▼
Authentication Response

This procedure allows the network and UE to authenticate each other using the configured subscription information.

🔒 Security Mode Procedure

Following authentication, the network sends:

Security Mode Command

The UE responds through an uplink NAS message.

This establishes the NAS security context required for protected signalling.

🧩 Initial Context Setup

The AMF subsequently initiates the UE context establishment towards the gNB.

The capture contains:

InitialContextSetupRequest

followed by:

InitialContextSetupResponse

This represents the establishment of the required UE context between the 5G Core and the gNB.

🌐 PDU Session Establishment

The experiment also captured:

PDUSessionResourceSetupRequest

and:

PDUSessionResourceSetupResponse

This demonstrates that the UE proceeded beyond basic registration towards PDU session establishment.
